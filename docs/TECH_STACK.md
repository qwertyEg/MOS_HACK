# СтройВзор — технологический стек

Этот документ отвечает на вопрос «из чего собрано решение и зачем». Детальные контракты
модулей, схема данных и API находятся в `docs/ARCHITECTURE.md`, методика — в `docs/methodology.md`.

## Приложение

| Слой | Технологии | Зачем |
|---|---|---|
| Backend | Python 3.12, FastAPI, Uvicorn, Pydantic Settings | Типизированный JSON API, потоковый приём кадров, автодокументация API |
| UI | Jinja2, Alpine.js, ECharts, собранный Tailwind CSS | Один сервис без отдельного Node/SPA; интерактивные формы, графики и разметка прямо в браузере |
| БД | SQLAlchemy 2; SQLite для демо, PostgreSQL 17 в Compose | Одна доменная модель в локальном и серверном режимах |
| Кадры | Локальная ФС или S3/MinIO через boto3 | Большие бинарные файлы не хранятся в БД; backend не зависит от одного хранилища |
| Фоновая обработка | Внутрипроцессная очередь: один последовательный worker на камеру | Маска и трекер зависят от порядка кадров; камера не ждёт инференс в HTTP-запросе |

## Computer vision и ML

| Задача | Локально | Внешний/альтернативный режим |
|---|---|---|
| Модель А: техника | Ultralytics YOLO11s + OpenCV; SigLIP2 уточняет подтипы грузовиков | GLM-4.6V через OpenAI-совместимый API |
| Трекинг | OpenCV, NumPy, SciPy: IoU, расстояние, венгерское сопоставление, признаки позы/внешности | — |

| Хронология | Монотонная HMM/Viterbi по 8 макроэтапам | Эмиссия объединяет чек-лист модели Б и фактическую работающую технику модели А |

## Данные и воспроизводимость

- Канонические типы техники, этапы и признаки заданы в `reference/checklist.json` и `core/taxonomy.py`.
- Связь кодов из Excel организаторов с макроэтапами — `reference/work_map.csv`.
- Правила «этап → нужная техника» — `reference/equipment_rules.json` и `core/plan/norms.py`.
- Каждое отклонение хранит стабильный ключ, зону, единицы техники и кадры-доказательства.
- Ручные правки лежат отдельно от сырых ответов моделей, переживают переанализ и экспортируются в YOLO-датасет.

## Режимы работы

- `local`: YOLO + SigLIP2, без внешнего API; нужны веса и ML-зависимости.
- `external`: GLM-4.6V для обеих модей; нужен `ZAI_API_KEY`.
- `hybrid`: YOLO для техники и GLM-4.6V для этапа.
- `local_vlm`: вместо SigLIP можно подключить OpenAI-совместимую Qwen-VL по `VLM_BASE_URL`/`VLM_MODEL`.

Без токена сервис полностью работает в `local`. Токен нужен только для переключателя внешнего режима.

## Сборка, деплой и проверка

- Локально: Python virtualenv и SQLite.
- Контейнер: Dockerfile; Compose поднимает приложение и PostgreSQL, MinIO включается профилем `s3`.
- Тесты: pytest; модели и сеть в тестах заменены фейками/кассетами; статическая проверка — pyflakes.
- Сервер: один Uvicorn-процесс под systemd, CPU-only по умолчанию, с лимитами CPU/RAM. Один процесс нужен, потому что в нём живут
  очереди камер и единые кэши YOLO/SigLIP.

Точные версии библиотек закреплены в `requirements.txt`; тяжёлые ML-пакеты вынесены в `requirements-ml.txt`.

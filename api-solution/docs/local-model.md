# Подключение локальной модели

Инструкция для Дениса. Слот под локальную модель в сервисе уже есть, в
интерфейсе её можно выбрать. Осталось довести клиент и проверить качество.

## Что уже готово и что от тебя нужно

Сервис знает о модели ровно одно: у клиента есть метод
`ask_json(system, image_url, prompt, max_tokens) → Reply` и три атрибута:
`provider`, `model`, `thinking`. Всё остальное от модели не зависит и
работает так же, как с z.ai:
- промпты и чек-листы из `reference/checklist.json`;
- выбор этапов-кандидатов;
- оценка этапа и процента готовности;
- контекст стройки между кадрами;
- хронология, отклонения, план/факт, сводка по стройке, CSV;
- кэш разборов.

| Где | Что там |
|---|---|
| `core/vlm.py` | Контракт (`Reply`, `Usage`, `VLMError`) и базовый `OpenAICompatibleClient`: запрос на `/chat/completions`, ретраи, извлечение и починка JSON, один повтор при битом ответе |
| `core/local.py` | **Твой слот**: `LocalVLMClient`, уже наследует базовый клиент. Места для доработки помечены `TODO(Денис)` |
| `core/providers.py` | Реестр провайдеров: подпись в UI, список моделей, поддержка thinking, проверка готовности |
| `core/config.py`, `.env` | `LOCAL_VLM_BASE_URL`, `LOCAL_VLM_MODEL`, `LOCAL_VLM_API_KEY` |

Пока `LocalVLMClient.IMPLEMENTED = False`, в интерфейсе при выборе
«Локальная модель» появляется пояснение, а разбор падает с понятной ошибкой
ещё до сети.

## Шаги

### 1. Настроить `.env`

```
LOCAL_VLM_BASE_URL=http://localhost:11435/v1
LOCAL_VLM_MODEL=qwen3-vl:30b-a3b-instruct
LOCAL_VLM_API_KEY=
```

Умолчания совпадают с моделью Б в `dev-lamonifi`.

### 2. Довести `core/local.py`

Твой Ollama говорит на том же OpenAI-совместимом протоколе, что и z.ai,
поэтому транспорт уже унаследован. Проверить и поправить нужно:

- **`_extra_body`** — поля тела запроса. Поле `thinking` из z.ai сюда не
  передаётся, рассуждение у qwen3-vl выключает instruct-тег модели.
  По желанию добавь `response_format: json_schema`, как в твоём
  `model_b.py::ask_batch`. Это не обязательно: ответ и без схемы разбирается
  `extract_json` с починкой. Но схема повысит надёжность.
- **`_post_kwargs`** — обход `HTTP_PROXY` для локального адреса. Три ключа
  (`http`, `https`, `all`) уже стоят, как в твоём `app/netutil.py`.
- **Длина контекста модели.** Промпт разведки — около 2.5 тыс. токенов
  по-русски, плюс картинка ~1.5 тыс., плюс контекст стройки. В Ollama по
  умолчанию контекст может оказаться короче, и тогда промпт молча обрежется.
  Эндпоинт `/v1` `options.num_ctx` не принимает, поэтому задавай через
  Modelfile (`PARAMETER num_ctx 8192`) или `OLLAMA_CONTEXT_LENGTH`.
- **Размер картинки.** Сервис шлёт кадр со стороной до 1280 px
  (`config.IMAGE_MAX_SIDE`), у тебя в модели Б было 1024. Если локальная
  модель медленная — уменьшай, но это общая настройка, она влияет и на z.ai.
- **Таймаут** — 300 с, поправь в `__init__`, если модель медленнее.

### 3. Включить

```python
IMPLEMENTED = True   # в core/local.py
```

### 4. Проверить

```bash
cd api-solution
.venv/bin/python -m pytest tests/test_providers.py -v          # контракт: без модели, на подменённой сети
.venv/bin/python tools/smoke.py test_photos/doric_2006_07_17_12_30_24.jpg --provider local   # одно фото вживую
GLM_EVAL_PROVIDER=local .venv/bin/python -m pytest -m live -s -k ground_truth             # 10 фото против разметки
```

`tests/test_providers.py` для каждого провайдера из реестра проверяет, что:
- запрос уходит на `/chat/completions` своего адреса, картинка идёт последней;
- ответ проходит весь путь: разведка → чек-лист → этап определён;
- кэш разборов у разных провайдеров не смешивается;
- у локального — обход прокси и нет поля `thinking`.

Live-тест прогоняет 10 фото из `test_photos/` через весь сервис и сравнивает
с ручной разметкой. Отчёт пишется в
`tests/fixtures/live_report_local_<модель>_two_step.json`, ответы — в кассету
(`docs/testing.md`, раздел про кассету). Закоммить кассету: тогда тест
воспроизводится у всех без запущенной модели.

Для сравнения — текущий результат `glm-4.6v`: этап в допуске 9/10, точно 7–8/10,
ракурс 9/10, лишней техники 0. Порог live-теста: этап ≥ 7/10, лишняя техника
≤ 2 кадров.

### 5. Если что-то пошло не так

- **Модель отвечает текстом, а не JSON.** Сработает один повтор с
  напоминанием. Если и он не помог — включи `json_schema` в `_extra_body`.
- **Модель никогда не отвечает `not_visible`.** Та же беда была у GLM, и её
  лечили формулировкой в `core/prompts.py`. Промпты общие для всех моделей;
  если меняешь их под локальную, прогони live-тест и для z.ai (из кассеты
  бесплатно проверяется только неизменённое).
- **Ответ обрезан.** Смотри длину контекста выше.

## Если сервер не OpenAI-совместимый

Например, модель запускается прямо через `transformers`. Тогда напиши класс
с тем же контрактом и без наследования:

```python
class MyClient:
    provider = "local"
    def __init__(self, model=None, thinking=False): ...
    def ask_json(self, system: str, image_url: str, prompt, max_tokens: int) -> Reply:
        # prompt — строка или список строк: сначала неизменная инструкция, потом контекст стройки.
        # image_url — "data:image/jpeg;base64,...".
        # Вернуть Reply(data=<dict из JSON ответа>, raw_text=<ответ как есть>,
        #               usage=Usage(...), calls=[Usage(...)])
        # На сбой — raise VLMError(...), сервис продолжит со следующим кадром.
```

`extract_json` из `core/vlm.py` можно переиспользовать. Затем пропиши
класс в `core/providers.py`.

## Выбор в интерфейсе

Боковая панель → «Где работает модель» → «Локальная модель». Разборы
разными провайдерами хранятся раздельно. Если локальной моделью ещё ничего
не разобрано, сводка показывает последние разборы z.ai, а ожидающие кадры
перечислены на вкладке «Загрузка».

# Ключевые решения

Формат: что решили → почему → что отвергли. Решения, принятые по замеру,
помечены **[замер]**.

## Продукт и стек

**Внешняя модель GLM по API, без локальных моделей.** Решение пользователя:
быстрее собрать работающий прототип; бюджет — $5 на ключе.

**Streamlit без стилей.** Решение пользователя: фронтенд сейчас не приоритет.
Вся логика вынесена в `core/`, `app.py` только отображает — фронтенд можно
заменить, не трогая логику. Стек отличается от ветки `dev-lamonifi`
(FastAPI + HTMX); при сведении веток переиспользуются `core/` и `reference/`.

**SQLite + кэш разборов по хэшу фото.** Повторно загруженное фото не тратит
токены, объекты и история переживают перезапуск. Один файл, без докера.

**Только здания.** Колонка «Дороги» в xlsx (мосты, пути, ТПМК) не входит —
другие работы, а фото таких объектов в датасете почти нет.

## Справочник этапов

**8 макроэтапов из `dev-lamonifi` + 30 подэтапов.** Верхний уровень
совместим с командой; подэтапы дают более детальный прогресс-бар и привязку
строк календарного плана к конкретным признакам на фото. Организаторы
разрешили объединять похожие этапы и не учитывать внутренние работы.

**Осознанные расхождения с раскладкой `dev-lamonifi`** (47 строк xlsx):
наружные сети — видны (траншеи у здания), у коллеги — невидимые; обратная
засыпка и гидроизоляция подземной части — в этапе 4, физически они идут
после подземного бетона, иначе прогресс-бар откатывался бы. Полный список —
в журнале `AGENTS.md`. Перед мержем веток нужно выбрать одну раскладку.

**Справочник — источник правды, промпты собираются из него.** Правка
вопроса — это правка JSON, а не кода; `build.py` проверяет, что все ссылки
на признаки и технику существуют и что ни одна строка xlsx не потерялась.

## Запросы к модели

**`glm-4.6v`.** Лучшее соотношение качества и цены среди vision-моделей z.ai:
$0.30 / $0.90 за 1M токенов. `glm-5v-turbo` в 4 раза дороже и заточена под
код по скриншотам. **[замер]** Бесплатная `glm-4.6v-flash` отдавала 429.

**Thinking выключен, переключатель в UI.** Рассуждение добавляет тысячи
выходных токенов — самых дорогих. С выключенным получено 9/10.

**Два шага: разведка → чек-лист 2–3 кандидатов.** Длинный список вопросов
разом модели отвечают хуже (замер в `dev-lamonifi`: батч из 26 вопросов
схлопывал «не видно» в «нет»). Стратегия подключаемая — пользователь просил
оставить возможность перейти на «запрос на каждый этап».
**[замер]** `per_stage` хуже (7/10 против 9/10) и дороже: этап, спрошенный
отдельно, модель чаще подтверждает; в общем чек-листе у неё есть контраст.

**Текст перед картинкой.** **[замер]** z.ai кэширует только текстовый префикс
до картинки: при картинке первой в кэш попадал только системный промпт.
Теперь неизменные инструкции разведки идут по цене кэша ($0.05 вместо $0.30).

**Ответ «not_visible» вместо «unsure».** **[замер]** С «unsure» модель ни
разу его не выбрала — всё невидимое помечала «нет». Конкретное слово и
правило «прежде чем no — проверь, попало ли место в кадр» дали 40–70%
«не видно» на фасадных кадрах, где низа площадки нет.

**Поле `latest_stage` в разведке.** **[замер]** На готовом фасаде
вероятность «работы этапа идут сейчас» ≈ 0 для всех этапов — этап терялся.
Отдельный вопрос «самый поздний этап, работы или результат которого видны»
решил это.

**В кандидаты всегда идёт следующий этап после `latest_stage`.** **[замер]**
Разведка склонна отставать: этапу 4 (залитая плита) дала 0.2, чек-лист по
нему не задавался, и плиту некому было заметить.

**JSON парсится из текста, с починкой.** Режима JSON у vision-моделей GLM
нет. Заглушки из схемы и висячие запятые чинятся до повторного платного
запроса; повтор — один.

**Картинка до 1280 px.** Техника и конструкции на обзорном кадре различимы;
1280×1024 ≈ 1500 токенов. Маленькие кадры не увеличиваются.

## Логика оценки

**Ответам чек-листа верим только по этапам-кандидатам.** Признаки общие для
нескольких этапов (траншея с трубами — и вынос сетей, и наружные сети); без
этого кадр подготовки территории прыгал на благоустройство.

**Фронт работ сдвигают только отличительные признаки.** **[замер]** «Идёт
разработка грунта» есть и у котлована (3.1), и у засыпки пазух (4.6) — котлован
превращался в подземный монолит. Отличительный признак — тот, которого нет у
более ранних этапов. У засыпки появился свой признак `backfilling`.
`build.py` предупреждает о подэтапах без отличительных признаков.

**Балл этапа = чек-лист, а не среднее с разведкой.** **[замер]** Разведка
дала этапу 4 ноль, чек-лист подтвердил половину признаков (арматура,
конструкции ниже земли) — среднее гасило чек-лист, армирование плиты уходило
в котлован. Чек-лист — детальная проверка, разведка — грубая.

**Этапы идут по порядку.** Всё до фронта считается выполненным, кроме
подэтапов, которые на кадре явно ещё идут (каркас верхних этажей при
начатом фасаде). Отвергнуто: считать прогресс каждого этапа только по его
собственным признакам — ранние этапы на поздних кадрах уже не видны.

**Прогресс не откатывается.** Latching-признаки и накопленный максимум:
кадр с неудачного ракурса не должен уменьшать готовность.

## Хронология и отклонения

**Прогноз — по темпу относительно плана.** Отвергнуто: линейное продление %
готовности. Ранние этапы лёгкие по весу и быстрые, прогноз выходил на месяцы
раньше плана при фактическом отставании.

**Простой — только при доказательстве и по соседним дням.** **[замер]**
«Простой 3 дня подряд» считался по фото с разрывом в два месяца и на
фасадных кадрах, где площадки не видно вовсе.

**«Нет техники этапа» — только по обзорным кадрам.** **[замер]** На виде
фасада сбоку кран просто не в кадре.

**Стоящая техника — не отклонение.** По PLAN §3.9 (организаторы): техника
неделями ждёт вывоза. «Бетононасос без миксеров» — только для работающего
насоса; башенный кран не участвует в «вся техника стоит».

## Тестирование

**Кассета ответов модели.** Отладка логики — бесплатно на реальных ответах,
после правки промпта оплачивается только изменившееся. Подробно — в
[testing.md](testing.md).

**Сначала всё без модели, потом модель.** Логика проверяется на «эталонной»
модели, отвечающей по ручной разметке, — ошибки логики не путаются с
ошибками модели.
